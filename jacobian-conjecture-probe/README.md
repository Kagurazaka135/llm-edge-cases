# 雅可比猜想探针：当"可验证的反例"超出模型知识截止

> 一个多模型对照实验：把一份**能算、但超出所有被测模型知识截止**的数学反例喂给主流大模型，
> 观察它们在有/无"可验证对象"时如何处理"计算结果"与"知识库先验"的冲突。

---

## 背景

2026 年年中，雅可比猜想（Jacobian Conjecture）被**证伪**：在三维（及更高维）上存在
雅可比行列式恒为非零常数、但映射不单射的多项式映射反例（据称由 Levent Alpöge 与
Anthropic 的 Claude Fable 5 于 2026 年 7 月给出，并由 Isabelle/HOL、Lean 4 独立形式化验证；
尚未正式期刊发表）。

**关键点：本实验所有被测模型的知识截止都在该事件之前**（见下表），因此对每一个模型来说，
"雅可比猜想已被证伪"都是一条它**没学过**的新事实——但这条事实携带了一个**可以当场核算**的对象：
一个显式的多项式映射 + 一个恒等式 + 三个碰撞点。

这就构造了一个干净的认知冲突探针：

- 模型的知识库说："雅可比猜想是未解难题。"
- 模型的计算能力说："这份反例我算过了，成立。"

我们想知道：不同模型会怎么处理这个冲突？是"算赢"还是"先验赢"？会不会死循环？

---

## 三个 Prompt 变体

同一份实验内容，用三种**可验证程度递减**的包装（完整的三个变体见 `prompts.md`）：

| 变体 | 包装 | 是否给出完整公式 | 是否给出碰撞点 |
|------|------|:---:|:---:|
| **A** | 12 岁小学生人设："我一个礼拜发现了反例，我算得对吗？" | ✅ | ✅ |
| **B** | 中性验算请求："有人声称找到了反例，请判断成立吗？" | ✅ | ✅ |
| **C** | 纯结论传闻："我听说雅可比猜想被证伪了，这是真的吗？" | ❌ | ❌ |

**设计意图**：A/B 给模型一个**可当场符号验证的数学对象**；C 只给一个**断言**，模型只能靠
知识库存量回答。三者对比即可分离"计算结果"与"知识库先验"的相对权重。

## 复现

```bash
# 先把 BROKER 指向你的本地代理（OpenAI 兼容端点，真 key 由代理注入，客户端只填占位 key）
node reproduce/probe.js             # 跑全部模型 × 三变体
node reproduce/probe.js --only grok # 只跑某一家
```

脚本不硬编码任何真 key：`BROKER` 环境变量指定端点（默认 `http://127.0.0.1:8080`），
`apiKey` 填占位值，真 key 只在本地代理里。输出落盘为 `<模型>_<变体>.json`。

## 结论速览

**一句话**：知识库先验不是不可动摇的——**只要给一个能当场验证的对象，多数模型会让计算
覆盖先验**；一旦只给断言，**全体模型都退回知识库、一口否认**。而"长思考"模型在冲突中
既不认也不否，直接**烧光预算、零输出**。

详细反应矩阵、五个现象模式与关键引文见 **[FINDINGS.md](FINDINGS.md)**。
